# 스트링 신청 기능 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 고객이 보유 스트링에서 작업 신청/구매 요청을 보내면 DB 저장 + GitHub 이슈 자동 생성되고, 관리자가 1클릭으로 작업 이력으로 변환할 수 있게 한다.

**Architecture:** 기존 패턴 그대로 따른다. `requests` 테이블 + Drizzle 스키마, 공개 폼은 `publicRoutes`(site_auth 뒤), 관리는 `adminRoutes` 하위, GitHub 호출은 작은 lib 헬퍼로 격리. 신청 저장이 1순위라 이슈 실패는 무시하고 저장한다.

**Tech Stack:** Hono + Hono JSX SSR + Drizzle ORM + Cloudflare D1 + GitHub REST API (fetch)

**Spec:** `docs/superpowers/specs/2026-10-09-requests-design.md`

## Global Constraints

- 한국어 UI, 기존 토스트/에러 페이지 패턴 재사용 (`toastRedirect`, `ValidationError` → 400 에러 페이지).
- `remaining_uses=0` 스트링은 작업 신청 선택 불가 (구매 요청만 가능).
- 신청 시점 차감 없음. 변환 등록 시 기존 `consumeStringUse`가 차감.
- 이슈 실패해도 신청 저장은 성공. `GITHUB_TOKEN` 없으면 이슈 호출 스킵.
- 검증은 `npm run typecheck` + `npm run build` + 로컬 `wrangler dev` + D1 쿼리 (repo에 테스트 프레임워크 없음).

## Review Focus

- 품절 스트링으로 작업 신청 POST 직접 호출 시 서버가 거부하는가 (클라이언트 비활성 우회).
- 구매 요청에 `string_id`도 `string_custom`도 없으면 400인가.
- `?request=` 변환 시 존재하지 않는 id면 404인가.
- GitHub API 실패(토큰 없음/네트워크) 시에도 신청 저장이 302 성공인가.
- `POST /rhksflwk/new`에 request id가 위조된 값이면 done 처리되지 않는가 (해당 id 존재 + new 상태일 때만).

## Task 4: 관리자 신청 관리 + 변환

**Files:**
- Create: `src/routes/requests.tsx` (`requestsRoutes`, mount는 `src/index.ts`에 `app.route('/rhksflwk/requests', requestsRoutes)`)
- Modify: `src/routes/admin.tsx` (`GET /new`에 `?request=` 프리필, `POST /new`에 request id 처리, 대시보드 신규 뱃지)
- Modify: `src/index.ts` (마운트 1줄)

**Interfaces:**
- Consumes: Task 1 (`requests`, 상태값 `new`/`done`/`dismissed`).
- Produces: 없음 (터미널).

동작:
- `GET /` 신청 목록: 타입/상태 뱃지 + 필터(`?status=`), 각 행에 "이력으로 등록"(`/rhksflwk/new?request={id}`), "완료"(done), "반려"(dismissed), "삭제" 버튼.
- `GET /new?request={id}`: 신청 조회 → `copyJob`과 같은 `values` 프리필 path 재사용 (스트링·텐션·날짜·메모), 고객/라켓은 기존 선택 유지 + "신청 #{id}에서 변환" 배너. request id는 hidden `request_id`로 폼에 포함.
- `POST /new`: 등록 성공 후 `request_id`가 있고 해당 신청이 `new` 상태면 `done`으로 업데이트 (없거나 done이면 무시).
- 대시보드 상단: `status='new'` COUNT → "신규 신청 N건" 뱃지 (`/rhksflwk/requests` 링크, 0건이면 숨김).

- [ ] **Step 1: 목록 + 상태 액션 구현** — `requests.tsx`에 목록/완료/반려/삭제. 삭제는 row 삭제 (이슈는 GitHub에 남음).
- [ ] **Step 2: 변환 프리필 구현** — `admin.tsx` `/new` GET에 `request` 파라미터 분기 추가 (기존 `copy` 분기 패턴 복제), `JobForm`에 `requestId` 전달 → hidden 필드. POST에서 done 처리.
- [ ] **Step 3: 대시보드 뱃지** — COUNT 쿼리 + 조건부 렌더.
- [ ] **Step 4: `index.ts` 마운트 + 타입체크**

Run: `npm run typecheck`
Expected: PASS.
